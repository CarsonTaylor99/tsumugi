# 05 — Placeholders and QA

Two jobs: keep the model from breaking the game, and keep it from producing bad English.
The first is a correctness gate. The second is a quality signal.

---

## The placeholder contract

VN script lines are full of engine markup — line breaks, click-waits, ruby, colour spans,
voice triggers, variable interpolation. **The model must never see raw control codes**, and
what it emits must be mechanically verifiable.

### Masking

Stage 2 replaces each code with an indexed sentinel and records it:

```
raw:     [voice name="HMK_0142"]先輩……[r]わたし、ずっと[ruby text="す"]好[/ruby]きでした[p]
masked:  ⟦0⟧先輩……わたし、ずっと⟦1⟧好⟦2⟧きでした⟦3⟧
```

Note the `[r]` is *gone*, not masked — see the linebreak rule below.

### Sentinel design

Choose sentinels that (a) never occur in source text, (b) tokenise stably in the models you
actually use, (c) are unmistakable in the workbench. **Calibrate this against the real
model before committing** — some models happily corrupt unusual Unicode (`⟦1⟧` → `⟦l⟧`), and
whichever form survives a 200-line stress test wins. Record the winner in the project config.

### Rules per kind

| Kind | Model sees it? | May move? | Rule |
|---|---|---|---|
| `linebreak` | **no — stripped** | n/a | Japanese line breaks are meaningless for English layout. Strip at Stage 2, re-insert at Stage 7 from measured metrics. |
| `pagebreak` | yes | no | Must survive, anchored to end of unit. |
| `wait` / `click` | yes | no | Anchored to the same relative position. |
| `var` (`%hero%`) | yes | within line | **Exactly once.** Never inline the value. Surrounding grammar must be name-agnostic — no "Mr. ⟦0⟧". |
| `ruby_open` / `ruby_close` | yes | yes, as a pair | Balanced and properly nested, wrapping a contiguous span. |
| `style_open` / `style_close` | yes | yes, as a pair | Balanced. Emphasis should land on the equivalent English span. |
| `voice` / `se` | yes | no | Anchored to start. |
| `opaque` (unrecognised) | yes | no | Strictly preserved, position-anchored. Unknown semantics ⇒ maximum caution. |

### Validation

On every response, before anything is written:

1. Sentinel multiset matches expectation for all non-stripped kinds.
2. No invented sentinels, no corrupted sentinel text.
3. Paired kinds balanced and correctly nested.
4. Position-anchored kinds at the same anchor.
5. `var` kinds appear exactly once each.

**Failure escalation — queued, never inline.** Retry once on the *resident* model with the
validator's specific complaint. If it fails again, **queue it** and move on; the `retry`
model runs as a batched Pass 3 (`docs/04-llm.md`). Escalating inline would swap models
mid-run, and each swap evicts the KV prefix cache. Anything still failing after Pass 3 is
marked `failed` and left as source text with a visible marker.

Never hand-repair a violating response; a model that dropped a `var` also probably
mistranslated the line.

### Ruby is a special case

Furigana is usually pronunciation and should simply be dropped in English. But VNs use ruby
as a *device* — 運命 written, さだめ read; a term written one way and read another. When the
reading is not a plain phonetic match for the base, flag it as a **gimmick ruby** for human
decision rather than silently discarding meaning.

## Validators (deterministic, free, run on everything)

| # | Check | Severity |
|---|---|---|
| 1 | Placeholder contract | **fail** |
| 2 | Residual Japanese — kana/CJK in output, minus an allowlist | **fail** |
| 3 | Echo — output equals source | **fail** |
| 4 | Empty or whitespace-only output | **fail** |
| 5 | Encoding-representable in the target encoding | **fail** |
| 6 | Glossary compliance for `enforce: true` terms present in source | **fail** |
| 7 | Meta-commentary — "Here's the translation", "Note:", markdown fences, refusal text | **fail** |
| 8 | Honorific policy — matches the `style.yaml` decision | warn |
| 9 | Length budget — measured width vs textbox, pre-reflow | warn → Stage 7 |
| 10 | Line count exceeds the page limit after reflow | warn → Stage 7 |
| 11 | Duplicate divergence — same `SourceHash`, different English | warn |
| 12 | Speaker-name leakage — a name inlined where a `var` belongs | warn |
| 13 | Pronoun mismatch against the cast card in a single-speaker scene | warn |
| 14 | Degeneration — n-gram loops, runaway repetition | **fail** |
| 15 | Length ratio far outside the expected 1.5–2.5× band | warn |

Fails are retried. Warns are surfaced in the workbench and fed to the judge.

### Refusal is a real failure mode

VNs contain violence, sexual content, and adult themes. A model that refuses or quietly
bowdlerises mid-run degrades the translation without erroring — and it will do so
*inconsistently*, which is worse than doing so predictably. Validator 7 must detect refusal
text explicitly, and the `retry` binding should point at a model that handles the source
material. Treat a spike in validator-7 failures as a signal to change the `translate`
binding, not to tweak the prompt.

---

## The judge pass (LLM, cheap because it's selective)

Runs on: everything a validator warned about, everything that needed a retry, plus a **2%
random sample** as running quality telemetry.

Returns per line: `accuracy` 1–5, `fluency` 1–5, `voice_match` 1–5, plus a one-line note.
Anything below threshold joins the Pass 3 `retry` queue, then the human queue.

The random sample matters as much as the flagged set: it's the only way to know whether the
translation is *quietly* mediocre, since the failure mode of a decent model is bland-but-
valid English that trips no validator.

---

## What lands in the workbench

The review queue, ordered by expected value of the user's attention:

1. `failed` lines — still in Japanese, blocking a clean build
2. Low judge scores
3. Duplicate divergence — one decision fixes many lines
4. Glossary and honorific warnings — usually systemic, one fix repairs a class
5. Overflow that survived reflow
6. The 2% sample, for spot-reading quality

The point is that the user never scrolls 30,000 lines. They work a queue that is sorted by
how much each decision is worth.
